# 使用指南

按[快速开始](../README.md#快速开始)启动后端，再打开 Web 工作台或原生客户端。

## 创建评审

1. 填写名称和设计材料，设计内容为 10–8,000 字符。
2. 选择 1–8 项工程检查。
3. 选择评审方式并提交。
4. 如有澄清问题，填写回答并继续。
5. 查看报告中的结论和引用，按需导出。

| 方式 | 处理流程 |
|---|---|
| MCP / 助手评审 | 桌面助手读取材料并提交问题或报告，需要连接 MCP 服务 |
| 离线演示 / 离线模拟 | 固定程序生成示例结果，用于体验界面和流程，不调用模型 |

离线模式中，少于 100 字符的材料会触发一次澄清。AI 报告与工作台中的人工检查记录分别保存。

## 连接 MCP

MCP 服务通过 stdio 接收桌面助手的工具调用，并转发到已启动的后端。在支持 stdio MCP 的助手中配置以下启动命令，将路径替换为项目的绝对路径：

```text
uv --directory <项目绝对路径> run --frozen --no-sync python -m app.mcp_server
```

Windows 上使用 Codex 时，也可在项目目录运行 `./connect-mcp.ps1`。脚本将 `swe-workspace` 写入用户 MCP 配置；相同配置会跳过，同名但内容不同的配置会报错。配置后重载 MCP 服务，必要时新开聊天。

客户端提交 MCP 评审后，在已连接的助手中输入：

> 读取工作台中的待评审设计，按选定检查项给出带原文引用的报告；需要澄清时先提交问题。

助手提出问题后，可在任一客户端回答，再请助手继续处理。客户端在等待时更新状态；提交任务本身不会自动唤起桌面助手。

原生客户端顶部的“检查连接”只检测后端，不发送待确认的评审。连接失败时，“帮助”提供对应平台的启动与连接步骤。“等待助手”页面可复制包含评审 ID 的处理指令，发送给电脑助手继续处理；“正在处理”表示后端正在执行操作。

### 工具

| 工具 | 用途 |
|---|---|
| `get_check_catalog` | 搜索检查项 |
| `start_review` | 创建评审 |
| `list_pending_reviews` | 列出等待处理的评审 |
| `get_review_context` | 读取材料、来源和当前版本 |
| `submit_review_output` | 提交澄清问题或最终报告 |

## 在不同客户端继续

[Android](../android/README.md) 通过 ADB 转发连接电脑；[iOS 模拟器](../ios/README.md) 连接同一台 Mac 上的服务。客户端连接同一个后端时，共享评审列表、问题和报告。

例如，在 Web 创建评审，桌面助手提交澄清后，在手机回答；助手再次处理后，手机可以读取最终报告。

移动端会保存草稿、回答和最近读取的报告。网络结果未知时，使用“重试原提交”继续确认；收到版本冲突后，先刷新记录再提交。

结果保存到设备后才会清除待确认请求；本机保存失败也可用原请求重试。Android 启动时若记录损坏，会显示恢复页面并暂停写入，保留原文件；修复存储问题后可“重新读取本机记录”。

## 查看与导出

打开报告中的引用，可以查看评审时保存的原文快照。服务校验引用片段及来源摘要，结论是否得到充分支持仍需评审者判断。

Web 可导出 Markdown 或 JSON；原生客户端提供 Markdown 预览和系统分享。原工作台的 HTML 导出只包含人工记录，AI 历史通过报告导出保存。

## 回放示例报告

后端运行期间，在项目根目录执行：

```sh
uv run --no-sync python scripts/replay_demo.py
```

脚本通过 MCP 新建一条评审并提交[已保存的示例报告](../evidence/mcp-review.md)。列表中的“演示回放”记录可用于检查引用和导出流程；回放不调用模型。

## 常见问题

| 现象 | 处理方式 |
|---|---|
| 无法连接工作台 | 确认后端正在运行；Android 重新建立 ADB 转发；iOS 模拟器与后端需位于同一台 Mac |
| 一直显示等待助手 | 在连接 `swe-workspace` 的桌面助手中请求处理待评审记录 |
| 回答后仍在等待 | 请桌面助手继续处理最新版本的材料 |
| 提示版本冲突 | 刷新并核对最新状态，再提交保留的输入 |
| 不显示 token 或费用 | 模型调用由宿主管理，后端无法取得这些统计，相关字段为 `null` |
