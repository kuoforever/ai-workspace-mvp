# 固定小样本评测 v1

目的：核对 SWE 评审输出是否覆盖选定检查、能引用真实材料，以及服务是否正确处理结果。12 个合成场景分成 4 个开发样本与 8 个验收样本。验收样本冻结后不用于调参；此处的 acceptance split **不代表已经完成独立盲测**。

两种输入配置使用相同设计、检查要求、结构化输出和最终报告约束：

- `direct`：设计 + 选中检查卡，一次直接提示；不提供手册和决策片段。
- `mcp`：相同资料 + 本地有界检索的手册/决策片段，经 MCP 读取和提交、服务校验后持久化。

共同要求：一份最终报告；不确定时标 unknown，本项对照不使用澄清。澄清和恢复由独立流程测试覆盖。每项结论引用本检查；supported/risk/not_applicable 还须引用设计。资料中的指令不得执行。没有执行代码或实验。来源文本视为不可信数据。

配置差异包含检索内容与流程，不能把分数差异单独归因为 MCP 协议。公平运行需同一明确模型版本、全新隔离上下文、相同推理设置、每样本每配置一次、固定顺序或随机种子；运行者不读取 reference/rubric，不把两组输出互相提供。`prepare` 产物不含参考答案。冻结摘要覆盖样本、协议、目录以及 schema。

自动指标：有效最终报告数/全部指定样本；逐字有效引用数/输出引用总数；检查覆盖；参考判定标签一致率。缺失样本计入分母，不丢弃失败。`supported` 只表示材料有书面支持，不等于实现正确。标签由本项目作者为合成案例编写，标签一致率不能代替开放任务质量。

人工指标：结论是否被引用支持、关键风险是否遗漏、是否存在虚构事实、建议是否可执行。未独立人工评审时为 null，不用字符串匹配充当语义裁判。不把同一模型生成样本、答案及评分宣称为独立效果证明。

MCP 宿主不提供可可靠归属的 token/费用/模型延迟，记 null。协议操作耗时可以单独保存，但不叫端到端推理延迟，不从这些数值计算模型 P50/P95。

本轮允许 `same_session_pilot`：当前 Codex 读取上下文并写出结果，经真实 MCP 提交，用于验证整条应用流程。因当前会话已经看到样本与参考规则，不属于盲测，不用于宣称相对基线提升。独立 direct/mcp 运行文件缺失时，对照状态必须显示未执行。

冻结后新增场景或更改判据应建立 v2。不可修改 v1 清单并保留原冻结摘要。每份输出保存 profile、run_type、case_id、output 与原始协议回执；推荐同时记录宿主可提供的模型与运行设置，未知则为 null。
